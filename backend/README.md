# 長時間借用

右上角「長時間借用」表單包含場地、起訖日期、借用者姓名、聯絡方式與用途，不需要密碼。

## 相容目前正式後端

長時間借用直接沿用既有 GET 月份讀取及 `book` API，不需先部署新的包場後端。前端會讀取區間涉及的各月份，確認沒有衝突，再依序建立每天 08:00–18:00 的一般預約，包含開始日、結束日與週末，可跨月、跨年。借用者與聯絡方式保存在每一日的預約；用途加上長時間借用的日期區間。使用者可在月曆與每日預約表檢視、編輯或取消各日預約。

這是多次獨立的 API 寫入，並非一次不可分割的交易。送出期間會停用按鈕並顯示進度；遇到失敗就停止，不自動重試寫入，並指出已完成日數、未確認成功的日期及後續未送出的日期。以完全相同的場地、區間、借用者、聯絡方式與用途再次送出時，會重新讀取資料並略過已存在且完全相符的全天預約，避免重複建立。若需要取消整段，請逐日取消已建立的預約。目前正式服務未經本次寫入測試，避免改動真實預約。

## 可選的新後端

以下 `Code.gs` 是可選的參考後端，不是使用上述長時間借用功能的前置條件。既有區間包場紀錄仍會顯示並封鎖對應場地。

### 部署參考後端

儲存庫原本只有前端，未包含現行 Apps Script 原始碼。`Code.gs` 是依目前前端 API 與欄位製作的完整參考後端，**尚未部署或驗證正式試算表相容性**。請先取得現行 Apps Script 程式碼，比對既有權限、驗證、額外欄位與其他商業規則，再決定整合或替換。此版本沿用現行前端的公開 book/edit/cancel 呼叫，並不新增這三項操作的身分驗證；若現行後端有驗證規則，必須保留。

1. 備份試算表與現行 Apps Script，先使用測試試算表測試，勿直接覆蓋正式部署。
2. 預約工作表標題列需含：`預約ID`、`場地名稱`、`預約日期`、`開始時間`、`結束時間`、`借用者`、`聯絡方式`、`預訂用途`。日期使用 `yyyy-MM-dd`，時間使用 `HH:mm`；日期／時間儲存格亦支援以試算表時區轉換。其他欄位更新時保留。確認試算表時區為 `Asia/Taipei`。
3. 將 `Code.gs` 加入採用 V8 runtime 的 Apps Script 專案。在「專案設定 → 指令碼屬性」設定 `SPREADSHEET_ID`（試算表 ID）、`BOOKING_SHEET_NAME`（預設「預約紀錄」）。長時間借用的新增與取消不需要管理密碼。
4. 首次包場時建立「包場設定」工作表（id、roomName、startDate、endDate、reason），請勿手動改動欄位名稱；現行預約工作表不會自動建立或改標題。
5. 測試部署為網頁應用程式，以擁有試算表權限的帳號執行；存取設定需與原本公開網站相容。依 Google 介面完成所需授權。
6. 將測試部署 `/exec` 網址填入 `assets/app.js` 的 `WEB_APP_URL`。正式上線時也必須更新現有部署版本或更換網址。GET 可額外回傳 `capabilities.roomBlocks: true` 與 `blocks` 以顯示既有包場；長時間借用送出只需要原本支援的讀取與 `book` API。
7. 若使用發布 CSV/GViz 讀取一般預約，前端仍會向 Apps Script 讀取包場資料；包場表無需發布到網路。

測試新增「討論室」包場（例如 2026-10-06 至 2026-12-31）、確認開始日與結束日皆封鎖／其他場地仍可借、跨月月曆標示、無密碼新增與取消、直接 API book/edit 被拒絕、既有預約衝突、跨使用者重新載入與解除後恢復借用。不要對正式資料提交測試預約。

## 本機驗證

`node --test tests/backend.test.cjs` 執行使用記憶體試算表的後端 API 測試；不是 Google 平台整合測試。
啟動 `python3 -m http.server 8000` 後，執行 `python3 tests/blocks-ui.py`。需要 Python Playwright 與 Chromium；測試攔截所有後端請求，不會寫入正式資料。
